## 一、计费（D-122 · 含 D-131 库龄并入）

### 1.1 已有调研（P1-R07·2026-09-03 建，**不是空白**）

`P1-R07-租赁管理行业调研.md` §4.4 已给出结论，且 §五「双模型交叉验证」明确标注**双方调研共识**：

- **计费公式**：按天 × 数量（对标行业「箱天」计费）
- **起租判定**：租赁单**发货审核完成日**
- **止租判定**：退租单**验收完成日**（对标 CHEP 申报事件=计费截止、睿池「回收验收止租」）
- **计费明细行**：SKU／数量／起租日／止租日／天数／单价／小计
- **平均租期**：Σ(数量×租期) ÷ Σ数量（加权平均）
- **免租天数**：支持（对标 SAP RPM 的 rent free days）
- **结算链路**：月度对账单 → 开票 → 收款核销

> 与 G21 三段式（计费方式×周期单位×数值）的**冲突点**在于「周期单位是否保留年/月」——行业共识偏向按天，但项目现状三段式以月为主。

### 1.2 本次补充取证（行业计费模型谱系）

| 形态 | 行业实例 | 要点 |
|---|---|---|
| **按天（箱天）** | 循环包装企业招股书（港交所披露） | 以「箱天」为最小价值单元；同文档还列出发箱/重箱/收箱计费、两段式计费、按订单日租（FIFO 分批核销）、年租计费 |
| **三种定价模型** | PackControl 包装租赁模块 | ①周期定价（天/周/月/年＋开票周期，如每周四或每月 15 日）②余额定价（按对方持有量计租，可定义计费天数含不含节假日/归还日、免费阈值、峰谷差异化）③项目定价（按件/按量/阶梯） |
| **阶梯日单价** | 托盘租赁专利文献 | 1~30 天 0.40 元 → 31~60 天 0.35 → 61~90 天 0.30 → 91~180 天 0.20 → 181 天以上 0.15；用「速算补偿数」简化在租总费用计算 |
| **静态/动态双计费** | 喜悦智行 301198（P1-R07 已引） | 静态租赁＝单价×天数×数量；动态租赁＝单价×次数×数量 |
| **结算周期两式** | 托盘共用系统学术论文 | ①按周期结算（按月/季扣租）②按实际归还批次结算（每退一批结一次）；订单关闭模式亦分「按周期」与「按实际归还数量」 |

**对本项目的启示**：行业里「按天」与「按月」并非互斥——**计价单位按天、结算周期按月**是常见组合（P1-R07 的结论正是这个）。若采纳，G21 三段式的「周期单位」可保留年/月作为**结算周期**语义，计价则统一按天展开到账单明细。

## 二、库龄 / 在库时长（D-131 ＋ D-125 库存展示规则）

### 2.1 通用 ERP 的库存列设计（可借鉴）

**库龄定义**：存货入库起在仓放置时长（与应收账龄同理）；**周转天数**＝从入库到消耗/销售所历天数。

常见库龄分析列：库龄分段（0-30／31-60／61-90／90+ 天）、批次/入库单号、入库日期、库位/仓库/分类、数量/金额、周转率、实际周转天数 vs 标准周转天数、**责任动作与处理建议**（优先拣货/促销/跨仓调拨/退供/复检/冻结/计提减值提醒）。

**算法警示**（用友 T+ 口径）：`平均库存 =（首天期初一半 + 中间每天结存 + 末天结存一半）/ 天数`；传统「(期初+期末)/2」在期末为 0 等场景会失真，建议逐日加权。

### 2.2 租赁场景需要调整的地方（关键）

**通用 ERP「库龄越长越差」的逻辑在循环包装租赁不成立**——器具是循环资产，在库时间长可能是**周转慢**，也可能是**淡季正常闲置**。行业资料给出的租赁专属列：

- **在库时长**（可用状态存放时间）
- **在租时长 / 在外天数**（容器在客户处流转中）
- **流转次数 / 循环次数**（衡量周转效率，比时长更贴业务）
- **回收状态、待检、维修、报废**
- **客户持有天数、超期未归还预警**
- 单只容器资产编号（序列化管理）

> 未获公开资料：**循环包装租赁专属的库龄列设计**（搜索结果全为通用制造/流通业 ERP）。上列「租赁专属列」是检索到的行业方案（联友 CMS、SAP RPM、Supercycle）拼合出的建议，属**我方推断**，需标注为设计建议而非行业标准。

## 三、客户虚拟仓 / on-hire（D-006）

### 3.1 行业实践

| 来源 | 做法 |
|---|---|
| **联友科技 器具全生命周期平台（CMS）** | 设计理念＝「始终确保网络中**空箱库存透明**」；含供应订单、调配、异地调拨、异地还箱、路径优化；与工厂 ERP／承运商 TMS／客户 ERP 接口 |
| **SAP Returnable Packaging Management** | **可回收包装库存全程跟踪**＋租赁管理（租金计费）＋包装协议；以**序列化容器**为单位记录状态更新 |
| **Supercycle（循环商业平台）** | 以**序列化单品级库存**替代计数式库存，每件唯一序列号＋状态（unused/used/repairable/unrepairable），含 **logistics buffers（周转缓冲期）** 管理出租间隔 |
| **山东驭梦 可移动资产运营平台** | 出库时**器具预分配、生成库存占用**——与「在租/预占」状态直接相关 |
| **学术（苏州科技大学等）** | 以马尔可夫决策建模：系统状态＝「有可用器具可租(1)／无可用不可租(0)」，推导可租概率与最优策略；租期服从负指数分布 |

### 3.2 「客户虚拟仓」术语核查

**未获公开资料**：中文「客户虚拟仓」未见标准术语命中。行业里对应的是**「把在客户现场/下游厂的空箱视为企业库存的一部分做透明化管理」**（联友 CMS 的 closed-loop 透明化、SAP RPM 的全程跟踪）——即**库存透明化口径**，而非一种独立仓型。

**对本项目的启示**：原型已建 `XNC-` 前缀虚拟仓 + 库存查询客户端行（on-hire 口径），与行业「透明化」思路一致；D-006 待定的「虚拟仓 vs 纯状态维度」可考虑**两者并用**——虚拟仓承载"在哪"、状态维度承载"什么状态"，与 Supercycle 的「序列号+状态」双维度同构。
