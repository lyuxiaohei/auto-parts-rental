# P1-R07 租赁管理行业调研

> **项目**：汽车物流包装租赁软件开发
> **日期**：2026-09-02
> **调研执行**：GLM-5.3 Flash + Kimi K3 双模型独立调研，交叉验证
> **调研目的**：为 v2 原型的租赁模块定名、库存状态模型、组合/拆散方案、计费设计提供行业依据

---

## 一、结论速览

**金蝶/用友的"租赁"都不适合循环包装业务。** 金蝶云星空的「租赁资产」是承租方财务核算（新租赁准则，管"我租入的"）；用友 YonSuite「资产租赁」有出租闭环但按个体资产+期间计费，均无"在库/在租/在途"的实物循环状态模型。**行业对标应看 CHEP/路凯/睿池/Novacura 等专业循环包装运营方。**

---

## 二、调研结果对比

### 2.1 金蝶云星空 vs 用友

| 维度 | 金蝶云星空【实证】 | 用友 YonSuite / U8+【实证】 |
|---|---|---|
| 模块名 | 「租赁资产」（资产管理→与固定资产并列） | YonSuite「资产租赁」；U8+无独立租赁模块 |
| 定位 | **承租方**财务核算（新租赁准则 CAS 21） | YonSuite **有出租闭环**（租前申请→合同→交接→结算→收租） |
| 单据流 | 租赁合同→资产租入单→付款计划→利息确认→终止单 | 租出申请→合同→租赁物交接→结算→收租；NC/BIP 另有周转材租出 |
| 状态模型 | 单据审批态（暂存→提交→审核→反审核），无业务阶段 | 合同态（生效/冻结/终止/变更），无实物位置状态 |
| 循环租赁 | **无**。包装物仅落"周转材料"会计科目 | **无**。U8+ 无；NC/BIP 有建筑周转材但非循环包装 |
| 组合 | 有「组装拆卸单」+「套件 Kit」（父项虚拟计价/子件管实物） | U8+ 有「组装单/拆卸单」+「成套件」存货属性 |
| 计费 | 按期间（月/季/年付）生成付款计划 | 按期间；NC 周转材惯例"日租金×数量×天数" |

**两 Agent 共识**：金蝶/用友的"租赁"满足不了循环包装——金蝶是承租方核算，用友有出租但按"台/套"个体管理，**均无出租库存状态模型**。这是自研的核心空白。

### 2.2 循环包装行业 SaaS（按参考价值排序）

#### ① Novacura RPMS（国外，系统设计最完整）【实证】
- **状态模型**：在供应商处 → 在途 → 在客户处 → 生产使用中 → 空箱 → 已退回 + 隔离/待验证/过渡
- **权属解析**：收货时按合同规则自动判定 ownership = 供应商自有/客户自有/租赁
- **套装配置管理**：中央配置库维护套装-组件映射（box+inserts+lid）、替代件；退回时做完整性校验，缺件/损坏标记进隔离
- **周期性余额对账**：按站点/供应商/箱型盘点出对账单——解决租出数量纠纷

#### ② 集保 CHEP（全球最大托盘池）【实证】
- **计费**：按天计租 + Service fee + 丢失赔偿（lost equipment fee）
- **申报机制**：起租=入库申报，止租=出库申报（**申报事件即计费截止点**）
- **冲销机制**：transfer 支持收货方更正数量（先 reversal 再建新单）
- **收板三分类**：清洁直接再投用 / 维修后投用 / 报废拆解

#### ③ 路凯 Loscam（大中华区托盘龙头）【实证】
- **模块**：计费管理 / 流转管理（过户）/ 订单管理 / 维修分拣 / 供应采购 / 库存收发
- **"户口转移"**：托盘随货流转，租赁责任从 A 账户转到 B 账户
- **运营单据**（商务部指引）：起租、退租（含异地）、维修、仓储一体

#### ④ 喜悦智行 301198（汽车循环包装上市公司）【实证】
- **计费公式**（年报原文）：
  - 动态租赁 = 租金单价 × 租用数量 × **使用次数**
  - 静态租赁 = 租赁单价 × 租用天数 × 租用数量
- **组合成套类包装**（与 A+B→C 对应）：托盘单元+顶盖+箱体+衬垫组合配套
- **主导制定团体标准** T/ZZB0615-2018《组合式可循环厚壁吸塑包装单元》

#### ⑤ 睿池 ULP（汽车围板箱租赁）【实证】
- 「云箱管理系统」；一单一码一单元；货物发出后起算租金、回收验收止租

#### ⑥ SAP RPM（汽车行业方案）【实证】
- **Packaging Account（包装账户）**作第一维度（在谁账上）
- 计费支持 daily rent + rent free days（免租天数）

### 2.3 库存状态模型——四态是否合理？

**两 Agent 共识：主干正确，与行业"位置维度"同构，但需补终态。**

行业通用三维度（实证归纳）：
1. **位置/持有维度**：在库 → 在途 → 在客户端 → 已退回
2. **箱况维度**：可用 / 待检 → 维修中 → 报废（CHEP 收板三分类）
3. **权属维度**：自有 / 租入 / 客户自有（Novacura ownership、用友三权分立）

**修正建议**（GLM 提出，K3 验证）：

| 现四态 | 问题 | 建议 |
|---|---|---|
| 在途 = 退租未审核 | 是单据状态，且漏"租出在途" | 拆为 `在途-发`（租出途中）/ `在途-退`（退回途中=退租未审核，由退租单审核状态自动推导） |
| 退租库存 | 与"在库"差异本质是箱况未整理 | 改用 `待检`（行业"隔离/待验证"），归入箱况维度而非位置维度 |
| （缺） | 行业标配 | 补 `维修中` / `报废` 终态（第一期预留字段，不实现流转） |

**推荐三字段正交设计**：

| 字段 | 取值 | 说明 |
|---|---|---|
| `hold_status` 持有位置 | 在库 / 在途-发 / 在途-退 / 客户端 | 位置维度（四态报表=此字段视图） |
| `condition_status` 箱况 | 可用 / 待检 / 维修中 / 报废 | 第一期仅"可用/待检"两值流转 |
| `ownership_type` 权属 | 自有 / 租入 | 第一期恒"自有"，字段预留 |

### 2.4 组合/拆散（A+B→C）

**两 Agent 共识**：行业 SaaS 公开资料中无"多组件动态组合成新单元出租"的产品化功能（托盘池无此需求），**最接近的是 Novacura 套装配置 + 金蝶 Kit/BOM 模式**。

- Novacura：套装-组件映射 + 退回完整性校验（缺件走异常流程）
- 金蝶 Kit：父项虚拟计价、子件管实物库存
- 围板箱本身是"底托+围板+箱盖"物理套装，行业按"套"出租

**设计方案**（两 Agent 建议融合）：
- 「组合方案」（类 BOM）：父=C（组合单元编码），子=A×配比+B×配比
- 「组合单」：审核后 A/B 扣减、C 增加（成本自动归集）
- 「拆散单」：退租验收后按配方反向入库，可设损耗
- 出租可同时选 C（组合）或散件；退租按实况整退或拆散入库

| 系统 | 命名 |
|---|---|

| 用友 | 数智资产 / 资产云 |
| CHEP | 物流设备平台 |
| 路凯 | 路凯在线 |
| 睿池 | 云箱管理系统 |
| Novacura | Returnable Packaging Management（可循环包装管理） |
| 喜悦智行 | 租赁及运营服务 |
| 国标语境 | 托盘循环共用 / 单元化载具 / 器具租赁 |

**两 Agent 一致推荐：用「包装管理」而非「租赁管理」**。理由：
1. "租赁"在金蝶/用友语境已被财务租赁（承租方核算）占用
2. 客户业务本质是"包装资产池运营"（含组合/维修/流转），不只是"租"
3. 与行业系统命名逻辑一致（Novacura=可循环包装管理、睿池=云箱、CHEP=物流设备）

### 2.6 审核流

行业通用节点全集（商务部《托盘共用系统作业规范》+ CHEP/路凯运营）：

> 租赁协议 → 租赁单证 → 交接 → 退板/回收 → 分拣（质检）→ 维修 → 转移 → 储存 → 对账/结算 → 盘点

单据状态通用：草稿/待提交 → 已提交 → 已审核 → 执行中 → 已完成 → 已结算/已关闭，外加驳回/作废。

**补齐建议**：退租单应加"待收货/验收"节点（对应 CHEP 分拣、RPMS 完整性校验）；期末加"已结算"；全单据支持驳回与作废。

| 维度 | 金蝶（星空租赁资产） | 用友（YonSuite 资产租赁） | 行业 SaaS（CHEP/路凯/RPMS/睿池） |

## 四、v2 设计建议（综合两 Agent 共识）

### 4.1 菜单命名
**推荐「包装管理」**（备选"循环包装"/"载具管理"），二级菜单：
- 资产台账（箱况+权属维度）
- 租赁业务（租赁单 / 退租单）
- 组合管理（组合方案 / 组合单 / 拆散单）
- 库存查询（四态视图=hold_status 聚合）
- 计费结算（计费明细 / 月度对账单）
- 运营报表（平均租期 / 周转率 / 出租率）

### 4.2 库存四态字段设计
按 2.3 节三字段正交方案执行；第一期 hold_status 实现 4 值流转，condition_status 仅"可用/待检"，ownership_type 恒"自有"。

### 4.3 组合/拆散记录方案
按 2.4 节 BOM 式设计执行；退租验收时用户可选"整退入库"或"拆散入库"（按配方 A/B 散件入库，与袁丽晶"按 ABC 单独入库"一致）。

### 4.4 计费功能设计
- 起租 = 租赁单**发货审核完成日**
- 止租 = 退租单**验收完成日**（对标 CHEP 申报事件=计费截止、睿池"回收验收止租"）
- 计费明细行：SKU、数量、起租日、止租日、天数、单价、小计
- **平均租期** = Σ(数量×租期) ÷ Σ数量（加权平均）
- 支持免租天数（SAP RPM rent free days 对标）
- 月度对账单 → 开票 → 收款核销（与财务闭环衔接）

## 七、v2 深度调研：流程闭环、单据流转与菜单设计（2026-09-03 补充）

> 两 Agent 第二轮调研聚焦"具体怎么做"——流程闭环怎么走、单据怎么流转、菜单怎么设计。GLM 深入金蝶/用友单据级，K3 深入行业 SaaS 实现层。

### 7.1 金蝶云星空：套件 Kit 与组装拆卸（单据级）

**套件 Kit 模式（与 A+B→C 对应的标准实现）：**
- 父项物料设"套件"属性 → **不允许库存、不允许生产**；子项是正常物料（有实物库存）
- 销售订单选套件父项 → 自动按 BOM 展开子项行（数量可改）→ **价格按父项取**（按套收款）
- 销售出库单上**父项不更新库存，只有子件扣库存** ← 核心机制
- 应收单只携带父项（按套确认收入）；子项成本自动汇总为父项成本

**组装拆卸单：**
- 功能路径：【供应链】→【库存管理】→【组装拆卸】→【组装拆卸单】
- 事务类型=组装（子件↓成品↑）/ 拆卸（反向）；参照 BOM 单号展开子件
- 成品明细/子件明细双页签；支持 BOM 展开时子件自动匹配库存出库
- 成本规则：组装成品成本 = 子件成本之和 + 组装费用
- **销售订单可直接关联生成组装单**——订单触发组装

**单据流转机制："下推"式**
- 销售订单 ──下推──→ 发货通知单 ──下推──→ 销售出库单 ──下推──→ 销售发票
- 下游数量反写上游（出库数量回写订单行），达到发货下限自动关闭订单
- 信用校验挂在销售出库单保存时
- 监控报表"销售订单执行明细表"：一行订单展示"发货/出库/应收/开票/收款"五段执行

**菜单命名规律**：【模块】→【业务域】→【单据/动作】三级，按业务动作分组

### 7.2 用友 U8+ 资产租赁管理（租赁流程闭环最完整的官方模块）

```
资产管理
└─ 资产租赁管理
   ├─ 设备卡片（附卡：租赁页签 / 租金页签）
   ├─ 租赁申请
   ├─ 外部租赁：对外租出 / 对外租出归还 / 外部租入 / 外部租入归还
   ├─ 内部租赁：对内租出 / 归还（协同单据）
   ├─ 租金计算：应收租金计算 / 应付租金计算 / 租金收款 / 租金付款
   └─ 台账报表：租出及归还台账 / 租赁应收台账 / 租赁应付台账
```

**完整闭环**：租赁申请 → 对外租出单（审核→回写设备卡片→推式生成出库单）→ 按期应收租金计算 → 租金收款 → 对外租出归还

### 7.3 行业 SaaS：单据链路最完整的两家

**myCHEP（循环包装全球标杆）**：
```
开户签约 → 租赁订单（4种入口）→ 发货单 → 在租台账（按账户记 equipment-days）
 → 过户单 CMD（发出方申报→接收方确认）→ 退租申请 → 退租验收销账（回仓签收才停计费）★两阶段强制分离
 → 纠错冲销单（引用原单号，60天窗口）→ 周期发票 → 收款
```
特色：账户负库存自动挂起（后续来货释放）；丢失设备赔付前持续计日租

**傲蓝建筑设备/周材租赁（国产单据驱动最完整样本）**：
```
周材线：租出合约（计费规则载体）→ 租出单（起算租金）→ 报停单/调价单 → 回收单（止算租金，支持部分回收）
 → 丢损赔偿单（选合约自动带出在租明细）→ 租出结算单（按合约对账截止日自动生成）→ 租赁发票 → 租出收款单
设备线：合约 → 出库单 → 安装单 → 起租单（开始计费）→ 报停/停租/调价 → 拆卸单 → 回库单 → 丢损赔偿 → 结算 → 收款
```
★设备线的"起租单"是独立计费开关单据，与物流单据（出库/回库）解耦

**傲蓝菜单树（行业通用骨架）**：
- 设备租出管理：合约/出库/起租/停租/报停/拆卸/回库/丢损赔偿/调价/派工/一览表
- 周材租出管理：合约/租出单/回收单/丢损赔偿/报停/调价
- 维修保养管理：保养单/维修单/整改单/检查记录
- 租入管理：租入合约/租入单/归还单/丢损赔偿
- 财务管理：租出结算/租赁发票/收款/坏账/其他费用/租入付款
- 进销存管理：采购入库/销售/调仓/其他出入库
- 系统管理：材料/设备/仓库/客户/工程项目/丢损赔偿价/审核设置

### 7.4 关键行业规律（两 Agent 共识）

| 规律 | 说明 | 对我们的启示 |
|---|---|---|
| **退租申请 ≠ 验收销账** | CHEP：回仓签收才停计费；两阶段强制分离是行业铁律 | 退租单拆为"退租申请→验收确认"两个节点 |
| **计费=周期快照制** | 无一家逐单结算——后台持续累计，按月/对账截止日一键出结算单 | 计费引擎按日累计，月度生成对账单 |
| **起租/停租与物流解耦** | 傲蓝设备线：出库≠起租、回库≠停租，独立开关单据 | 租赁单发货≠自动起租，验收完成才止租 |
| **单据流转两种模式** | ERP"下推式"（订单自动生成出库→发票→收款）；行业 SaaS"参照式"（新建时选源单自动带出明细） | 我们用下推式（业务量小，自动化优先） |
| **丢损赔偿是独立单据** | 傲蓝：选合约自动带出在租明细、赔偿价有默认档案 | 退租验收后自动生成丢损赔偿单（非弹窗） |
| **审核节点独立设置** | 运腾：出库审核/入库审核/还回检测独立成菜单 | 我们的全模块审核状态流可做成参数化配置 |

### 7.5 菜单设计建议（基于行业对标综合）

**推荐菜单结构（v2 原型）**：

```
包装管理（替代原"租赁管理"，对标行业命名）
├─ 租赁台账：合约 / 租赁单 / 退租单（含验收节点）/ 丢损赔偿单
├─ 库存查询：四态视图（在库/在途/客户端/退租待检）
├─ 组合管理：组合方案（BOM）/ 组合单 / 拆散单
├─ 计费结算：计费明细 / 月度对账单 / 开票登记
├─ 运营报表：平均租期 / 周转率 / 出租率 / 丢失率
└─ 维修管理：维修单 / 报废单（第一期预留）
```

**单据流转设计**：

```
项目经理录入销售订单（代下单）
 → 订单审核 ──下推──→ 租赁单（自动生成）
 → 租赁单发货 ──下推──→ 组合出库单（散件扣减+组合件增加）
 → 客户使用（在租台账持续计费）
 → 退租申请（录入退租单）──下推──→ 验收单（确认散件入库+缺损核对）
 → 验收通过 ──下推──→ 丢损赔偿单（如有缺损）
 → 月度：计费引擎汇总 ──生成──→ 对账单 ──下推──→ 开票登记 ──下推──→ 收款核销
```
