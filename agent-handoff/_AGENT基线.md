## 四、⚠️ 历史事故与真相（防再误解）

1. **原型生成脚本已删除**（2026-09-02）。**原型一律手工维护**，任何新脚本禁止裸 `open('w')` 整页写入。批量改动用"读取-精确替换"式脚本，每步 assert 匹配数。
2. **30 页"空 `<script>`+孤立 `</style>`"坏块**（2026-09-03 发现并修复）：历史标注注入 bug，导致 13 页 modal HTML 被吞（弹窗点击无反应）、17 页标注层被吞。已全部修复；新注入脚本须检查标签配平。
3. **混合行尾文件是假象**：sed/cat -A 管道会吞 `\r`，判断行尾用 Python 二进制读。
4. **外发 HTML（P1-R01*.html）是快照**，直接改会被下次转换覆盖。
5. **会话教训（2026-09-04）**：①"押金结算"曾被我当会议需求补进流程图——实际会议 0 提及，属过度推断，已撤（教训：图上每个节点必须能引会议原文，推断须标"设计决策待确认"）②造词要避免（"配对页与台账"被道远指出不懂，改"录单页与台账"）③L3/L4 定性先查转写原文再落图。
6. **批量脚本教训（2026-09-04 L3/L4 改造实录）**：①侧边栏批量插入的跳过条件不能用"页面含某链接字符串"判断（会误跳含该跳转的业务页/漏跳 selected 页）——应以"页面是否已含新菜单行"精确判断；②生成函数返回格式化模板时漏写 `% 变量` 会静默产出字面 `%s`（必须抽查生成文件内容，DOM 计数通过≠文本正确）；③Playwright 断言跳转时 `pg.url` 中文被 percent-encode，需 `unquote()` 后再判断；`innerText` 受可见性影响，校验文本用 `textContent`。
7. **并行会话冲突事故（2026-09-07 晚，无损收场但全靠对方协作）**：同一工作区两个 agent 同时改原型——A 路（业务场景 /goal）与 B 路（应付详情数据驱动重构）在 18:33~18:46 窗口先后写同一批文件，B 重写 `应付账单.html`＋`弹窗/应付账单详情.html`（波及面经其备份目录 backup-demo-data-20260907 核实仅此 2 文件＋新建 `_data/` 两文件，A 路其余改动未被触碰）时物理删除了 A 刚打入的静态预付时间线节点，但将内容协作式收编进 demo-data.js（措辞一致、表格行保留），净内容损失 0——**这是运气不是机制，若 B 盲目覆盖即丢数据**。四个次生后果（均已核实）与教训：①**全量审计快照横跨碰撞窗口**——audit_results.json 18:47:35 完成，其中应付页"0 问题"读数来自 2 分钟前已被替换的静态版，审计期间有并行写入则数字只是时点快照，**接手 agent 的验证门必须自己重跑，不引用历史报告数字**；②**`_data/` 是 untracked 目录**——`git commit -a`/`git add -u` 都不会带上它，提交后页面引用空目录＝详情空壳，**多股改动入库一律 `git add -A`**；③**两套备份语义不同**——`backup-biz-20260907`＝A 改前原始态（应付无预付）/ `backup-demo-data-20260907`＝B 改前＝**含预收预付行＋节点的最后静态完整态**，还原前先分清要哪套；④**架构分裂期改层规则**——应付详情改 demo-data.js、其余弹窗改页面 HTML（详见第三节技术要点对应条目）。**铁律：原型目录同一时间只允许一个 agent 写**——开工前查原型目录内最近文件 mtime ≥30 分钟无变化（尤其 `_data/`）；自己的会话用完即关，不得挂后台闲置。
