## 一、任务目标

把原型里的**弹窗形态**按 `admin-ui-spec` 载体选择规范做一次全量归位：**新建/编辑/详情/审核/表单维护类一律改为独立页面，纯二次确认类保留弹窗**。目标是消除「页内嵌 modal + `弹窗/` 独立模板」的双层维护，让表单与详情跑在统一的页面容器里（宽度自适应、不受 `max-height` 约束）。

现状：**78 个弹窗模板**分布在 9 个模块；改页面后页面数增加、模板数减少，**HTML 总数基本持平**。

## 二、载体判定规则（逐弹窗先判定，再动手）

|---|---|---|
| 详情类（26） | **页面** | 四段式内容超一屏 |
| 新建 / 录单类（21） | **页面** | 字段多或含明细表 |

## 六、默认决策表（执行中不再提问·逐条按此办）

### 载体与命名
- 纯二次确认（无表单字段）→ **保留弹窗**；含字段的「确认」→ 页面
- 新页命名：`<实体>新建/详情/审核.html`（实体取宿主列表页的菜单名，如「物料档案」）
- 原弹窗名与新页名的对应写进本批执行记录

### 页面形态（一律照样板，不重新设计）
- 表单页：页标题 ＋ 分卡片表单 ＋ **底部固定提交条（按钮居中）**；卡片数按内容分（信息卡／明细卡）
- 表单控件宽度**统一 380px**（表格内按列分配）；日期字段 `type="date"`
- 备注：并入所属表单卡**末尾**，`<textarea>`（`.input-box` 外壳·`min-height:72px`·`resize:vertical`）
- 详情页：单据头字段网格 ＋ 明细表 ＋ 关联互溯链 ＋ 流转时间线
- 审核页：详情结构 ＋ 决策区（结论 radio ＋ 意见 textarea ＋ 后果提示）＋ 提交条
- 页顶**不放**「返回列表」按钮（提交条「取消」已承担返回）
- 弹窗宽度与弹窗内字段仅当其**保留为弹窗**时才适用（640/780px·92vh）

### 数据与联动
- **入口接线**：`openModal('xModal')` → `go('相对路径')`，**含 `demo-data.js` 里该实体的 `ops[].act`**（列表行操作是数据驱动渲染的，只改页面静态 HTML 不生效）
- 页面内新增的 `onclick` 必须自带 DOM 副作用（`go()` / `closeModal()` 等），否则全站 audit 判死按钮
- 字段选项**不写死**：字典取 `DEMO_DATA.dictItems` 按 `category` 过滤；主数据取对应实体（如 `products`）
- 页面按需引入 `<script src="../_data/demo-data.js"></script>`（沿用相对层级）
- 联动字段（如物料编码 ↔ 物料名称）任一变更另一自动同步，并带出可推导字段（规格/单位）
- 只读/自动计算字段用**文本 `td.auto-cell`**（本项目 audit 无 `class="auto"` 豁免）

### 范围边界
- **不动业务口径**：字段含义、状态流、单号前缀、审批层级一律不变，只换载体与规范化样式
- **不动已改好的页面**（G33 三页、试点页）；**不动保留弹窗**
- 若某弹窗的宿主列表页正被并行修改 → 该弹窗跳过并记失败清单（禁抢改）

### 兜底自愈
- 弹窗内容含宿主页强耦合脚本（如专用渲染器）→ 先剥离为页面内联脚本；剥离失败则保留弹窗并记失败清单
- 配平/结构异常 → 用栈扫描定位，修不了则回滚该弹窗（从备份还原）并记失败清单
- 复核发现某弹窗本就合规 → 记「无改动」继续，不计失败
