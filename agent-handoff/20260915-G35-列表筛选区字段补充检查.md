这是一次**只读检查**：把原型里每个列表页的筛选区，与「列表实际字段」和「后台管理系统的常规筛选惯例」对照，找出**该有而没有**的筛选项，产出一份带优先级的建议清单。

## 三、检查判据（常规惯例·逐条对照表格实际字段）

| # | 判据 | 说明 |
|---|---|---|
| 1 | 表格有**状态**列 → 应有状态筛选 | 单据状态/合作状态/启用停用等 |
| 2 | 表格有**类型/分类**列 → 应有类型筛选 | 账单类型/退货类型/出库类型/物料类型等 |
| 3 | 表格有**主体**列 → 应有主体筛选 | 客户／供应商／项目／物料 |
| 4 | 表格有**日期**列 → 应有日期区间筛选 | 单据日期/建单日期/入库日期等（`range:true`） |
| 5 | 表格有**人员**列 → 宜有人员筛选 | 经办人／负责人／制单人／盘点人／下单人 |

## 五、任务分组

### T1 逐页提取（33 页）
对每个列表页提取三项：**现有筛选项**（`ff-label` 文本）、**表格列**（`<th>` 文本）、**页面类型**（列表/看板/专用页）。输出原始对照表。

### T2 逐页比对
按第三节八条判据，逐页找出「表格里有、筛选区没有」的字段，形成初判清单。

### T3 分级与去噪
对每个建议项定优先级并去重：
- **P0 必备**——状态、主体（客户/供应商/项目）、单号这类高频维度，缺了明显不便
- **P1 常用**——类型、日期区间、库房、人员
- **P2 可选**——金额区间、低频维度

同时标注**不建议补**的项（如明细展开字段、几乎不重复的值），避免清单变成「什么都加」。

### T4 产出与落盘
写 `_scan_tmpdir/g35_筛选区补充建议.md`，结构：
1. 概览（33 页逐页一行汇总：现有项数／建议补充数／优先级分布）
2. 逐页明细（表格：列表页｜现有筛选｜表格关键字段｜建议补充｜优先级｜理由）
3. 共性问题（如「日期列普遍缺区间筛选」「主体维度缺失集中在 XX 类页面」）
4. 不建议补充项与理由

## 六、默认决策表（执行中不再提问·逐条按此办）

### 检查口径
- 判据以第三节八条为准；判据未覆盖的字段，按「后台系统常见筛选维度」常识判断并在理由栏写明
- 一个字段同时多角色（如「客户/供应商」统一列）→ 建议归并为一条「往来单位」筛选
- 已有筛选 ≥7 项的页面 → 重点转为**查漏**：核对状态/主体/日期区间三项，不主动建议 P2 项
- 已有筛选 ≤3 项的页面（如角色管理）→ 列为重点补强对象

### 产出规范
- 优先级取值仅 P0/P1/P2；每项必须写理由（引用判据编号）
- 覆盖全部 33 页，每页必须有结论行（「无需补充」也要写，并给理由）
- 日期区间统一标注 `range:true` 写法（与 filter-bar.md 一致）
- 术语一律 P1-R04 现行词

### 范围边界
- **只读**：不修改任何原型文件、不改 `_data/`、不动交接文档（除本任务产出的建议文档）
- 不评估筛选区的**样式/布局**（那是 G36 与 admin-ui-spec 的范畴），只看**字段维度的缺失情况**

### 兜底自愈
- 某页结构特殊（无标准 `ff-label`）→ 记录「非标准筛选区」并跳过该项，不强行类比
- 提取不到表格列（表格由 JS 渲染）→ 从 `demo-data.js` 对应实体的 `fields` 反查字段名，并在建议里标注数据来源
- 复核发现某页已完整 → 记「无需补充」继续，不计失败
