# 交互载体选择（页面 vs 弹窗 vs 抽屉）

一个交互该用页面还是弹窗，按本规范判定，不凭手感。**默认用页面**；只有「轻交互」才用弹窗。

## 一、选择规则

| 交互类型 | 载体 | 判据 |
|---|---|---|
| 新建 / 录入表单（字段 ≥3 或含明细行） | **页面** | 空间需求大，弹窗塞不下必然触发内部滚动 |
| 编辑表单 | **页面** | 同上 |
| 单据 / 实体详情 | **页面** | 四段式内容（单据头 + 明细表 + 关联互溯链 + 流转时间线）远超一屏 |
| 审核（看明细 + 填意见 + 给结论） | **页面** | 需同时呈现明细与决策区 |
| 多步向导 | **页面** | 弹窗容不下多步 |
| 二次确认（停用 / 删除 / 提交前确认） | **弹窗** | 一句话确认，跳页过重；保留弹窗形态 |
| 结果反馈 / 轻提示 | **弹窗** 或 toast | 不需要独立上下文 |
| 选择器（选原单 / 选物料 / 选库位） | **弹窗** | 需保留当前表单已填内容，选完回填继续 |
| 校验拦截 / 警告（库存不足、必填缺失） | **弹窗** | 阻断当前操作而不离开上下文 |
| 查阅型明细（流水 / 履历 / 版本记录） | **页面** 或 **抽屉** | 内容短可弹窗，超过一屏用页面 |

## 二、判定三问（拿不准时按序问）

1. **用户要不要边看原页面边操作？** 要 → 弹窗（选择器、确认、警告）；不要 → 下一问
2. **内容是否超过一屏，或含明细表？** 是 → 页面；不是 → 下一问
3. **操作完要不要回到原上下文（列表筛选 / 页签 / 滚动位置）？** 要 → 弹窗；不要 → 页面

按序问到第一个「是」即定；三问皆否时用页面（默认）。

## 三、页面的三种骨架

| 骨架 | 用途 | 结构 |
|---|---|---|
| **表单页** | 新建 / 编辑 | 页标题 + 分卡片表单（`components/form.md`）+ 底部固定提交条（取消 / 保存：**按钮居中**） |
| **详情页** | 单据 / 实体查看 | 单据头字段网格 + 明细表 + 关联单据互溯链 + 流转时间线 |
| **审核页** | 审核决策 | 详情页结构 + 决策区（结论单选 + 意见框 + 业务后果提示）+ 提交条 |

三者共用 `common/page-skeleton.md` 的壳（顶栏 + 侧边栏 + 内容区）。

- **返回入口**：提交条已是「取消 → 回列表」时，页顶**不再**重复放「返回列表」按钮；无提交条的页面（如详情页）才在顶部左侧给「← 返回列表」
- **横向空间**：详情页字段网格可用三列（`dgrid.c3`）利用页面宽度，弹窗只能两列

## 四、弹窗的边界

保留弹窗的形态**只做四件事：确认、提示、选择、拦截**。

- **单一职责**：一个弹窗只解决一件事
- **宽度两档**：`.modal` 640px（确认 / 提示）、`.modal-lg` 780px（选择器内容多时）；`max-width:92vw` 兜底
- **禁止**在弹窗里放：明细表编辑、多段表单、多步流程——这类一律页面
- **禁止**多层嵌套：弹窗内再打开另一个弹窗

## 五、为什么（页面化的收益）

1. **消除双层维护**——弹窗要在「宿主页面内嵌 modal」与「独立模板」两份之间同步，改一处必改另一处，是持续的成本与事故源；页面只有一份
2. **尺寸与样式统一**——页面走内容区卡片体系，宽度自适应视口，不受 `max-height` 上限与固定像素宽度约束
3. **可深链、可刷新**——页面有独立 URL，能直接打开、刷新后保持

## 六、弹窗改页面的迁移要点

改造既有弹窗时逐条对照：

- **入口**：`openModal('xxxModal')` → `go('相对路径')`
- **文件**：宿主页内嵌 `modal-overlay` 块与独立模板文件一并删除，只留页面文件（**这是收益所在，不要保留兼容副本**）
- **菜单**：多数迁移页不进侧边栏，属「菜单外页面」（从列表页按钮进入），对照表按此登记
- **标注**：挂在弹窗键上的标注 pin 迁到页面键
- **列表状态**：跳页会丢列表筛选 / 页签，返回时用 URL 参数回填；原型期接受重查
- **分批执行**：按模块分批改造，每批跑完审计与标注迁移再进下一批，不一次性全量铺开
