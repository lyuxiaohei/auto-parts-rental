## §A 形态 A：Claude Code /goal（条件式）

机制要点（官方文档口径）：
- 条件 ≤**4000 字符**；设置后每轮结束由小模型评估（通过/未达/不可能三判）
- 评估器**只看对话中已呈现的证据**，不自己跑命令——验证命令的输出必须打印在对话里
- 配 **auto 模式**才真正无人值守（turn 内免批准 + turn 间自动续）
- 长任务书放文件（如 `TASK.md`），条件引用之，绕开字符上限

**条件三要素**（缺一不可）：
1. 一个可度量的终态（测试退出码 / 文件数 / 空队列）
2. 明示的验证方式（"`npm test` exits 0" / "`git status` is clean"）
3. 不可破坏的约束（"no other test file is modified"）

**条件模板**（v4 结构化版——【块】+ 逐条分行，禁大段连排）：

```
/goal 〈一句话任务概述〉。工作目录（命令与交接文档全部相对路径之根，不依赖会话 cwd）：〈项目绝对根目录〉

【交接文档 · 双层路由，先读全文再动手】
〈agent-handoff/_AGENT基线.md 绝对路径〉（项目上下文与铁律，常驻滚动）
〈agent-handoff/YYYYMMDD-G序号-任务slug.md 绝对路径〉（本 goal 任务全量细则）

【前置校验 · 先于一切】
〈状态标记期望值，逐条一行〉
〈任一不符 = 已执行/并发 → 写失败清单（路径在交接文档头部）后收尾，禁止重做〉

【任务】
T1 〈概述，细节见交接文档任务节〉
T2 〈…〉

【完成判定 · 证据全部贴进对话】
1. 〈命令〉→〈期望输出形态，一行写死〉
2. 〈…逐条独立成行，可数预期写死数字〉

【约束】
- 〈不可破坏项，一行一条〉
- 〈无人值守声明：不提问/按交接文档默认决策表/拿不准最简默认+收尾注明〉
- 〈执行完成后回写三件（硬性）：任务文档标完成+执行记录；_索引.md 挂 G 号与 commit 哈希；_AGENT基线.md 同步新现状〉
- 〈git 批次对应（硬性）：一 goal 至少一提交，哈希回填任务文档头部与索引〉
- 〈assert 失败 → 跳过 → 记失败清单 → 继续〉

or stop after N turns
```

要点：`or stop after N turns` 限额防失控；把"证据已贴在对话"写进完成判定（评估器只认对话内内容）；**v4 格式铁律——至少两级结构（块标记 + 块内逐条分行），任何单段连排 ≤3 行，并列语义点禁止"①②③"内联塞法**；**v5 路径自包含——命令面向零上下文新会话：头部声明项目绝对根目录，交接文档/失败清单/状态标记/跨项目参考文件用绝对路径，交付前 os.path.exists 逐条实测贴输出**；**v6 交接文档模式——不生成一次性任务书：项目常驻 `agent-handoff/AGENT-交接文档.md`（无则先建/有则追加任务节）承载全部任务与上下文，条件只做路由，执行收尾回写台账与基线**；**v7 交接文档双层——常驻 `_AGENT基线.md`（全项目唯一滚动）+ 每 goal 一任务文档 `YYYYMMDD-G序号-任务slug.md` + `_索引.md` 台账（挂 commit 哈希）；禁止单文档无限追加任务节；收尾回写三件+哈希回填为硬性**。

## §B 形态 B：长任务书式（Paseo agent / 一次性长 prompt）

整段自包含，粘贴即跑。骨架七段全量内嵌，开头必带无人值守声明。

**骨架**（本身就是 markdown 两级结构——【】块/## 标题为一级、块内条目为二级；交付时保持层级，禁把条目并段连排）：

```markdown
/goal 对〈目标物〉执行〈N 组任务〉（〈截止语境〉）。全程无人值守：所有决策已由〈谁〉拍板，
按本命令的默认决策表执行，不需要也不得向用户提问；拿不准的按最简合理默认执行并在收尾报告
"默认决策"节注明。

【前置状态校验（防重复/并发执行）】
执行前检查〈状态标记〉（版本行/里程碑文件/提交号）：〈期望值〉。若已是执行后状态（版本更高/
标记存在）→ 停止并写失败清单注明"疑似已执行"，禁止重做。

【第 0 步·上下文获取（动手前必做）】
1. 〈纪律/事故教训文档——第四节全部逐条适用，或按任务动作类型反查全集〉
2. 〈现状基线：已完成的样板/勿重做项〉
3. 〈任务清单文档〉
4. 〈工具与豁免口径〉

【任务一…N】每组：改动点清单 + 明确的不动项（"严禁触碰 XX"）

【默认决策表】
- 〈数据规范：日期/单号规则/状态色/行数〉
- 〈样式形态：具体 CSS 值/阈值〉
- 〈范围边界：哪些页面纳入/排除〉
- 〈兜底自愈：个别不符合时先做什么再做什么，仍不行则豁免留档〉

【失败处理策略（无人值守铁律）】
任何 assert 失败/锚点不匹配/预期外结构：跳过该项，记入〈失败清单文件路径〉（页面+原因），
继续下一项。禁止卡住等待、禁止对不确定结构猜测性改写。收尾报告必须包含失败清单（可为空）。

【纪律（违反=返工）】
- 全部"读取-精确替换"脚本+assert+幂等；〈项目特定铁律 1-3 条〉
- 〈备份/还原规则：按原相对路径〉
- 〈高危操作规则：改 JS/移动文件后必跑什么〉
- 〈环境教训：路径编码（中文路径用 python 内嵌）/文件移动禁止覆盖同名/其他〉

【验证门（全部满足才算完成，证据形态逐条点名）】
1. 〈全量命令级〉：〈命令〉，证据＝〈该命令的输出形态，如"死链 0/链接总数 N 一行输出"〉
2. 〈抽验级〉：证据＝〈如"Playwright 输出 N 页 PASS/FAIL 清单"〉+ 截图存放路径
3. 〈量化预期写死〉：〈可数的全部写死数字——页数分布/阈值/文件数，不留执行者解释空间〉
4. 〈复评级〉：证据＝〈grep/断言输出行〉

【收尾（回写三件+git 批次为硬性）】
1. 本 goal 任务文档（agent-handoff/YYYYMMDD-G序号-任务slug.md）标已完成+执行记录+commit 哈希回填头部
2. _索引.md 追加行：日期/G序号/任务名/状态/commit 哈希/文件名
3. _AGENT基线.md 同步新现状（若有）
4. 〈失败清单结论行已贴出（空清单给"无失败项"结论）〉；〈不留垃圾/不动归档区〉

（A 形态时：任务细节与默认决策表放独立任务书文件，goal 本体 ≤4000 字符只留路由+前置校验+
判定+约束；末尾加 or stop after N turns 限额）
```

## §C 三道保险写法要点

**保险 1 · 默认决策表**
- 逐条问自己："执行 agent 走到这会不会犹豫？"会→补一条默认值
- 高频项：示例数据规范（日期/单号/状态色/行数）、样式具体值、阈值（字符数/页数）、"复核后无需改动"的处理（记录不算失败）、新元素是否入标注/台账
- 措辞模板："〈情形〉→ 按〈默认值〉处理；复核发现已合规则记录'无改动'继续"

**保险 2 · 失败跳过留档**
- 三禁：禁止卡住等待、禁止猜测改写、禁止静默吞掉
- 留档文件固定路径 + 字段（页面/任务/原因）+ 收尾必须给结论（含空清单结论）
- 效果：任务永不死锁，人回来只看一份失败清单

**保险 3 · 验证门机器判定**
- 每条完成条件都能被命令输出/断言结果证明，杜绝"自称完成"
- 三层：全量命令级（工具+期望输出）→ 抽验级（抽样断言+截图）→ 复评级（文档判定）
- A 形态额外要求：输出贴进对话（评估器只看对话内证据）

## §D 真实案例（包装租赁项目 2026-09-05，两次无人值守实战提炼）

**案例 1：四组全量处理（B 形态）**
- 任务：①操作栏冻结全站挂类 ②弹窗宽度 680→780px 全站 ③演示场景 14⚠️+1❌ 修复 ④菜单重组（仅排序）
- 默认决策表示例："采购单号 SO-→PO-：页面与 A04 pin selector 同步替换（不匹配则保留原单号并在报告注明）""新增示例行统一规范：日期 2026-09-01~05、每页 1 行、新行不加 A04 pin"
- 验证门：全量审计 0/0/0 + Playwright 抽验冻结 10 页/弹窗 10 页/菜单顺序 + 场景表 76/76 ✅
- 实测结果：无人值守跑完，失败清单仅 1 条"复核已合规无改动"记录

**案例 2：弹窗美观度（B 形态，含自愈兜底）**
- 默认决策表示例（自愈链）："超行且文本 ≤34 字的，弹窗内联加宽至 720px 复测；仍超则该行跨全宽再复测；仍超记入报告豁免；>34 字长说明文案天然允许换行直接豁免"
- 教训固化：三形态枚举（空格版/紧凑版/带旧兜底版）逐一枚举替换，不识别则跳过留档

**通用教训（写进纪律段的素材）**
- 还原备份必须按原相对路径（丢子目录会产生游离文件，审计死链当场抓获）
- 块内坐标位移必须覆盖 y=/y1=/y2=/path 全形式，改完跑对齐断言
- 改内嵌 JS 字符串后必跑该页 audit（引号丢失→语法坏→整页功能挂）
- **引用项目教训时禁用"括号列举法"**——列举必然不全（09-07 事故：括号列了 4 条漏了 Playwright 中文 URL unquote/textContent 两条，恰与该任务验证门直接相关）。正确写法：要么写"第 X 节全部纪律，逐条适用"，要么按任务动作类型反查（涉及 Playwright→查校验类教训；涉及 HTML 块→查配平类；涉及备份还原→查路径类），列出与任务动作有交集的全集

**案例 3：结构化排版打回（投资项目 2026-09-07，催生 v4 格式铁律）**
- 首版 /goal 条件把前置校验/完成判定/约束各糊成单段（"①②③④⑤⑥"内联塞），用户当场反馈"结构性不强，可读性差"
- 重排为【前置校验】【任务】【完成判定】【约束】四块 + 判定六条逐行编号（977 字符，远低于 4000 上限）→ 即刻通过
- 固化：v4 格式铁律 + 自检新增结构化项（实测块数/最长连排行数，非目测）
- 教训：条件是给两个读者看的——执行 agent 按块定位入口、人回头按块复查；结构即可用性，且结构化几乎不耗字符预算

**案例 4：路径丢失打回（投资项目 2026-09-07，催生 v5 路径自包含）**
- 条件只写相对路径且未声明项目根；用户指出"路径都搞丢了，你确认新的 agent 能找到吗？这是拿给没有上下文的新会话执行的"
- 修复：命令头部一行绝对工作目录声明 + 任务书/失败清单改绝对路径 + 任务书顶部加根路径声明块；python os.path.exists 对全部关键路径逐条实测（含"应不存在"的标记文件）贴输出为证
- 固化：v5 路径自包含铁律 + 自检"第 0 步自包含"项扩为"口径自包含 + 路径可寻（实测）"
- 教训：/goal 命令的默认受众是**零上下文新会话**——它没有本会话的 cwd、没有对话记忆，路径锚点必须自带给足

**案例 5：任务书模式废止（投资项目 2026-09-07，催生 v6 交接文档模式）**
- v5 版为 goal 配了独立一次性任务书文件；用户反馈"不需要任务书，如果项目中没有 agent 交接文档则新建一个，用于 agent 读取任务和上下文"
- 重构：新建项目常驻 `agent-handoff/AGENT-交接文档.md`（①上下文常驻基线 ②当前任务全量 ③任务台账），任务书内容吸收后删除；条件改为路由交接文档绝对路径；收尾要求回写交接文档（状态/台账/基线）
- 教训：一次性任务书是"每任务一个孤岛"，交接文档是"项目级 agent 记忆"——上下文一次沉淀、多任务复用、执行状态可续，且新 goal 只追加任务节不再造文件

**案例 6：单文档追加模式废止（包装租赁项目 2026-09-08，催生 v7 交接文档双层）**
- v6 模式落地后单一交接文档滚到 500+ 行 13 节（基线+9 轮任务书+变更记录混合）；用户反馈"一个 goal 命令一个交接文档，不要一直放在一个文档中；文件夹中的交接文档命名要能分辨时间和 git 批次；P1-R05 归档或放入新文件夹"
- 重构：`agent-handoff/` 三层——`_AGENT基线.md`（从巨型文档抽基线节，全项目唯一滚动）+ `YYYYMMDD-G序号-任务slug.md`（每 goal 新建）+ `_索引.md`（台账挂 commit 哈希）；巨型文档抽基线后归档冻结
- 同轮升硬性：收尾回写三件进自检门；git 一 goal 一提交+哈希回填；资源互斥（单 agent 写+mtime 并发检测）
- 教训：交接文档的正确粒度是"**基线唯一 + 任务分散**"——基线是记忆（要集中滚动），任务是凭据（要独立可溯、按时间/git 批次可检索）；单文档无限追加会让记忆与凭据互相淹没
