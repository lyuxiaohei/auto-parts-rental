# Goal Creator：编写无人值守长任务命令

把一个多步骤任务写成**不需要人盯、不会中途提问、完成与否机器可判**的命令。核心是三道保险（缺一不可）：

1. **默认决策表**——所有可预见的小决策预先定死；声明"不需要也不得向用户提问，拿不准按最简合理默认执行并在收尾报告注明"
2. **失败处理策略**——assert 失败/结构不符时跳过该项、记入失败清单文件、继续下一项；禁止卡住等待、禁止对不确定结构猜测性改写
3. **验证门**——全部完成条件写成机器可判定（命令退出码、输出断言、抽验清单），"全部满足才算完成"

## 工作流

### 1. 澄清目标（问用户，≤3 问）

必问：①任务终态是什么（改完哪些东西/跑通什么）？②执行环境（Claude Code /goal？Paseo agent？普通长 prompt？）？③有没有必须守的约束与已知坑（项目纪律/事故教训）？

可选：截止时间（写入命令头部制造优先级）、是否允许文件移动等敏感操作。

### 2. 选形态（按执行环境路由到模板）

- **形态 A：Claude Code `/goal`（条件式）**——条件上限 4000 字符；任务细节与上下文放**项目 agent 交接文档**（项目中没有则先建），条件只做路由。见 [goal-templates.md](references/goal-templates.md) §A
- **形态 B：长任务书式（Paseo agent / 一次性长 prompt）**——全量内嵌，自包含。见 [goal-templates.md](references/goal-templates.md) §B

判断依据：执行方是不是 Claude Code 本 session 的 /goal 机制（是→A）；发给另一个 agent 会话整段执行（→B）。

### 3. 写命令（按模板骨架填充）

骨架固定七段（B 形态；A 形态条件部分浓缩为三要素）：

```
【第 0 步·上下文获取】必读文件清单（纪律/教训/现状基线/工具）
【任务】分解为编号任务组，每组含明确改动点
【默认决策表】逐项列出可预见小决策的预定值（数据规范/样式形态/阈值/范围边界）
【失败处理策略】跳过+留档+继续；失败清单文件路径
【纪律】精确替换+assert+幂等；备份按原相对路径；项目特定铁律
【验证门】命令级（退出码/输出断言）+ 抽验级（Playwright/截图）+ 复评级
【收尾】文档台账更新要求；失败清单结论（可为空）
```

**格式铁律（v4）：markdown 结构化，至少两级，禁大段连排**

- **一级结构 = 分块标题**：任务书用 `##`/`###` markdown 标题；/goal 条件用 `【前置校验】【任务】【完成判定】【约束】` 块标记（纯文本终端里同样成立）
- **二级结构 = 块内条目逐条分行**：编号 `1.`、列表 `-`、表格行；完成判定、约束、默认决策表**必须**逐条独立成行
- **连排上限**：任何单段连排不超过 3 行；两个以上并列语义点禁止挤进一段（含"①②③"内联塞法）
- 为什么：命令有两个读者——执行 agent 按块定位入口，人回头按块复查；结构即可用性（2026-09-07 投资项目实战：条件糊排被用户当场打回"结构性不强，可读性差"）

**路径自包含（v5）：命令面向零上下文新会话，cwd 不可依赖**

- 命令**头部必须写明项目绝对根目录**，声明"全部相对路径以此根拼接"
- 关键文件（任务书、失败清单、状态标记、跨项目参考文件）一律**绝对路径**
- 其余相对路径可用，但必须有根声明兜底
- 交付前实测：对命令与任务书里的每条绝对路径跑 `os.path.exists`，输出贴进对话为证（2026-09-07 投资项目实战：条件只写相对路径未声明根，用户指出"路径都搞丢了，新 agent 找不到"）

**交接文档双层模式（v7）：常驻基线 + 每 goal 一文档，禁止单文档无限追加**

- 文件夹 `agent-handoff/`（项目根新建）三层结构：
  1. `_AGENT基线.md`——项目上下文常驻基线（现状/关键路径绝对地址/口径纪律铁律/工具），**全项目唯一、滚动更新**；项目中没有则先建（从既有巨型交接文档抽取基线节）
  2. `YYYYMMDD-G<两位序号>-<任务slug>.md`——**一个 goal 命令一个任务文档**（前置校验/任务组/默认决策表/验证门/执行记录），命名可分辨时间（日期）与 git 批次（G 序号）；严禁把新任务追加进旧任务文档
  3. `_索引.md`——台账：日期/G序号/任务名/状态/**commit 哈希**/文件名
- git 批次对应（硬性）：一 goal 至少一提交；收尾时把 commit 哈希回填任务文档头部与索引行（创建时无哈希不进文件名，避免收尾重命名）
- /goal 条件 = 路由（**基线文档 + 本 goal 任务文档**两个绝对路径）+ 前置校验 + 完成判定 + 约束
- 执行收尾时**必须回写**：任务文档标已完成+执行记录、索引台账挂 G 号与 commit 哈希、基线同步新现状——基线是项目级 agent 记忆，任务文档是该次 goal 的完整凭据
- 存量巨型交接文档（基线+任务书+变更记录混合体）处置：抽取基线节进 `_AGENT基线.md` 后整体归档冻结（归档目录或移入 agent-handoff/ 标注冻结），不再滚动（2026-09-08 包装租赁项目实战：用户明确"一个 goal 命令一个交接文档，不要一直放在一个文档中；命名要能分辨时间和 git 批次"）

### 4. 无人值守自检（交付前逐条过——**必须逐条写出检查证据**，如"搜'确认'得 0 处"，禁止只打勾；字面过清单=未检查）

> 三种死法画面（自检时对照回想，比规则更有约束力）：没有默认决策表→agent 半路停下来等回复，无人值守变无人干活；没有失败留档→agent 卡死或瞎猜改坏结构；验证门不机器判定→agent 自称完成，回头一查没做完。

**自检前先确认技能版本**：本技能由实战反馈持续迭代（v1 基础三保险→v2 教训反查→v3 前置校验/证据点名/自检证据化→v4 markdown 结构化排版→v5 路径自包含→v6 交接文档模式→v7 交接文档双层：常驻基线+每 goal 一文档+git 批次哈希回填→v8 交付提示精简：触发即要 goal，不做形态科普），若当前会话开始早于最近一次迭代，重读 SKILL.md 确认拿到的是最新清单。

- [ ] 有没有任何一处会让 agent 停下来等确认？（搜"是否/要不要/确认后"类措辞——有即改为默认决策）
- [ ] 结构化达标吗？（证据＝条件含 ≥4 个块标记或任务书含 ≥4 个标题、关键清单逐条分行、最长连排段 ≤3 行——实测计数，非目测）
- [ ] 自拟内容（示例数据/文案/阈值）是否全部在默认决策表里给了规范？
- [ ] 历史教训引用是否完整？（禁括号列举法——按任务动作类型反查教训全集：Playwright 校验/HTML 块改动/备份还原/JS 字符串各自对应的教训是否都进纪律段；环境类教训如中文路径编码、文件移动禁覆盖同名是否适用）
- [ ] 有前置状态校验吗？（防重复/并发执行：版本行/标记文件期望值，已执行则停止写失败清单）
- [ ] 验证门每条都点名了证据形态吗？（"python 断言输出/Playwright N 页 PASS 清单/grep 输出行/失败清单结论行"——比"输出贴对话"更防含糊；可数预期全部写死数字）
- [ ] 失败时每一步都知道怎么办？（跳过-留档-继续，无死路）
- [ ] 完成条件是否全部机器可判定？（评估器/人只看输出就能判，不依赖主观）
- [ ] 第 0 步是否自包含？（新会话无前文也能拿到全部口径，**且路径可寻**：命令含绝对根目录声明、任务书/失败清单为绝对路径——os.path.exists 实测输出贴对话，非目测）
- [ ] 官方口径（A 形态）：证据须落对话——验证命令的输出要打印出来让评估器读到；细节放任务书文件、goal 本体 ≤4000 字符；加 or stop after N turns
- [ ] 收尾段是否含"回写交接文档"硬性要求？（任务文档标完成+执行记录 / 索引台账挂 G 号与 commit 哈希 / 基线同步新现状——三件缺一即补，2026-09-08 用户拍板升硬性）
- [ ] 是否含 git 批次对应与资源互斥？（一 goal 至少一提交+哈希回填；涉及共享工作区文件写入时必含"同一工作区同一时刻只允许本 agent 一个写"+mtime 并发检测前置校验）

## 产出与迭代

交付物即 goal 命令——按触发规则找本技能的用户（点名 /goal-creator）意图已明确：拿到即可执行的 goal，**不做形态科普、不解释斜杠有无**（v8 · 2026-09-10 道远反馈两轮收敛：先问"没有斜杠 agent 能识别？"，再拍板"B 形态不需要，冗余了——按触发规则触发技能时，就是需要 goal 的"）。交付时只附一句运行环境提示：

- Claude Code：`/goal` + 条件文本，auto 模式无人值守
- Paseo / 其他 agent：命令整段粘贴为首条消息执行
- 用户级技能改动后，项目内分发副本（`skills/goal-creator/`，如有）同版本同步并随下一次 git 提交入库

执行后回收失败清单与默认决策命中情况，回填模板。
