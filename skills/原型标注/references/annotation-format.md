# 标注数据格式与编写指南（现行：A03 json → notes-data.js 双处·手动维护）

> **现行真值源（0918 G52 起）**：`P3-R01-A03-标注数据.json`（项目侧）→ 人工同步到 `_data/notes-data.js`（运行时）。**两处必须同步改，逐条手动 Edit**——不允许脚本批量注入/刷改（annotate.py 已退役）。下文格式对两处通用（notes-data.js 里是同构的 JS 对象）。

## 数据格式

```json
{
  "_meta": {
    "project": "汽车物流包装租赁",
    "source": "P1-R01-需求梳理与功能框架.md（FP/REQ 编码）",
    "date": "2026-09-01"
  },
  "仓储作业/小组装列表.html": [
    {
      "id": 1,
      "selector": "<button class=\"btn btn-primary\"",
      "title": "新增组装单 → 弹窗录单",
      "note": "点击弹出「小组装录单」窗口：A+B→C，记录运营方/时间/数量。\n组装后子件库存转母件，库存双视角实时更新。",
      "fp": "FP3-02",
      "req": "REQ-06"
    },
    {
      "id": 2,
      "aud": "dev",
      "selector": "<th>循环状态</th>",
      "title": "循环状态口径沿革",
      "note": "拍板沿革/实现口径类内容写这里（进紫色抽屉，正式版不出现）。"
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | 页内序号 1..n，即数字角标与抽屉排序；同页新增 dev 条目接续编号 |
| `aud` |  | **双轨分轨字段（0919/0920 拍板）**：不写＝业务轨（? 圆标＋小弹窗，面向最终用户）；`"dev"`＝开发轨（紫色数字角标＋抽屉，仅开发过程看）。字段位置在 id 之后 |
| `selector` | ✓ | **原文子串**（非 CSS 选择器）：该元素开标签的一段唯一原文，如 `<button class="btn btn-primary"`、`<th>循环状态</th>`。**现行仅作人工定位参考**——运行时匹配只按页面 `data-note="N"` 数字，不做子串替换 |
| `title` | ✓ | 条目标题（≤20 字；? 弹窗标题栏即用它） |
| `note` |  | 说明正文，`\n` 换行。**biz 条目必须面向最终用户：禁写 D 号/会议/人名/日期等过程信息（过程信息拆去 dev 条目）**；dev 条目写拍板沿革/实现口径 |
| `fp` / `req` |  | 回链需求文档编码，显示为紫色标签；`_meta` 含 `codes` 映射时自动展开为「编码 · 全称」并附出处块 |

## `_meta.codes` 代号映射（可选，推荐）

```json
"_meta": {
  "codes": {
    "FP3-02": {"name": "小组装单", "desc": "A+B→C，记录运营方/时间/数量；组装后子件库存转母件"},
    "REQ-06": {"name": "小组装管理节点", "desc": "记录 A+B→C 的组装时间与数量；库存双视角（零件/组合）"}
  },
  "codesSource": "P1-R01 三/四章 FP·REQ 表（唯一维护处）"
}
```

- 作用：标签不再裸显代号——变「FP3-02 · 小组装单」，条目附完整出处说明，读者无需翻需求文档。
- 维护：从需求文档 FP/REQ 表人工维护；映射缺的编码自动降级为裸代号标签。

## 从需求文档提取标注（逐条手写）

1. 需求基线（P1-R01 类文档）有 FP 功能点表：每模块「编码 | 功能点 | 要点说明 | 需求」。
2. 对原型每个页面，找出承载的 FP，逐条写条目并判 biz/dev：
   - 列表页：按钮（新增/导出/批量操作）、关键状态列、筛选区新概念
   - 弹窗：触发按钮处标一条，note 里写弹窗内容摘要
   - 表单/录单页：每个业务规则一个条目（如"组装后子件转母件"）
3. selector 写法：**优先带 class 的开标签片段**；避免纯中文文本（重名率高）；长度适中且全页唯一——写完 grep 验证唯一。
4. 一个锚点只挂一个 `data-note`；同一元素多条说明合并进一个条目的 note（或拆 biz/dev 两条挂同锚）。

## 锚点定位速查（人工比对用·勿脚本批量生成）

| 锚类型 | 特征 | 注意 |
|---|---|---|
| 卡片标题 | `<h3 class="card-title">主名</h3>` | **h3 与 div 两种形态并存**（详情页/双表页常用 div 带内联 style），找锚两种都要兜 |
| 表头 | `<th>列名</th>` | 最稳的锚，列名全站基本唯一 |
| 按钮 | `<button …>按钮文字</button>` | 同名按钮（如多个「提交验收」）带 onclick 消歧 |

## 现行交互（notes-drawer 双轨·共享件自动渲染）

- **? 圆标（biz）**：锚点文字后内联常显（素材图 18px·标题/表头后水平对齐·按钮内并入文本），点击弹小弹窗（标题＋说明＋× ·点外/Esc 亦关）；不进抽屉、不悬停。
- **数字角标（dev）**：标注开启态显示，点击开右侧抽屉并定位条目（「开发」紫徽标）。
- 开关三通道：右下角「标注 N」fab / `Alt+N` / `?notes=1`（仅当页初始开）；默认不展示、不跨页记忆；本页无数据 fab 隐藏。
- 页面侧只有 `data-note="N"`＋`</body>` 前两行共享件引用——从页面复制 selector 片段可含 `data-note` 属性，无碍（不做子串替换匹配）。
