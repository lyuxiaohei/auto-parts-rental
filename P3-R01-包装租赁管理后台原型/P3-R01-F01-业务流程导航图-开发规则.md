6. `#srcPop` 会议依据弹窗 + `SRC_DATA` 脚本 + ia-fix 脚本（勿删）

## 3. 文本规则（6 级封顶，尺寸必须是 4 的倍数）

| 级别 | 字体 | 字号 | 字重 | 颜色 |
|---|---|---|---|---|
| 泳道/支线标题 | Geist | 16 | 700 | ink |
| 节点名 | Geist | 12 | 600 | ink |
| 节点副标 | Geist Mono | 8 | 400 | muted（枢纽节点用 accent） |
| 注记/决策文 | Geist Mono | 8 | 400 | soft |
| 箭头标签 | Geist Mono | 8 | 400 | muted + 纸色遮罩，离线 6–10px |
| 徽章/图例/eyebrow | Geist Mono | 8 | 500–600 | accent / soft |

配套条文：

- **链接一律"灰句子 + 蓝词"，禁止整句蓝色**（蓝词 = 可点）。
- 任何文本不得超出所在节点框（用浏览器 `getComputedTextLength` 实测）。溢出只有两条出路：缩短文字，或节点按宽度档升级。**禁止硬塞**。
- 坐标、宽高、间距全部落在 4px 网格上。

## 4. 节点类型（仅 6 种，颜色即语义）

| 类型 | 样式 | 语义 |
|---|---|---|
| 流程节点 | 白底 + ink 边 | 可点击页面 |
| 枢纽页 | accent 底 + accent 边 | **只给库存查询**（含在库/租入在库形态） |
| 入口/出口/交棒 | 灰底 + muted 边 | 跨线入口、交棒财务/其他泳道的节点 |
| 资产分类框 | ink 3% 底 + ink 30% 边 | 自有资产/租入资产等分类，非页面、不可点 |
| BOM 自动节点 | ink 2% 底 + ink 35% **虚线边**（4,3） | BOM/组合计算：自动增减组件库存，本身无库存 |
| 决策备注框 | ink 2% 底 + rule-solid **虚线边**（4,3） | 拍板/决策变更记录，不参与流程 |

- 主线节点统一 **140×56，rx=6，间距 16**。例外宽档：F 来源聚合框 280、T1 在库节点 170、分类框 96、交棒 chip 96。
- 交棒 chip：96×56 灰底单行，格式「⇢ Tn 名称」，四条租赁线统一以此收尾。
- 「第一期实现」徽章：四条租赁线都有，64×16，accent 色，紧跟标题右侧。

## 5. 主线结构规则

- 每条泳道 = 标题行（16 标题 ＋ 徽章 ＋ 📎 固定 x=620 ＋ 右对齐灰色注记）→ 节点链 → 交棒收尾。
- 泳道之间一根 rule 色分隔线，不得缺席。
- 决策备注只用一种形式：**右侧虚线框**（位置：该行右侧空白区）。
- T1 结构例外（内容决定）：入口行 → 主干竖线 → ①②③ 三分支。**编号不得重复**；分支线带箭头，主干不带。
- T1→T2 跨泳道交棒用灰色虚线（5,4）连接，落点是 T2「租入在库」顶边。

## 6. 支线结构规则（S1–S6）

- chip 高 36、rx=6，宽度两档：**120 标准 / 170 长名**。
- 标题 16，**不画英文 eyebrow**（v3.4 起删除）。
- 箭头：有顺序语义才画（S2/S4/S6），纯并列不画（S1/S3/S5）；同一行内禁止有的画有的不画。
- 双向关系只用一种写法：副标「⟷ 对象页」，禁止独立的 ⟷ 字符。
- 灰底 = 由主线衔接的入口节点（如 S1 按零件入库、S6 我的待办）。

## 7. 连接线与符号

- 折线一律正交圆角（r=8），禁止斜线。
- 箭头符号只有三种：`→` 流向、`⇢` 交棒、`⟷` 双向（仅副标）。禁用 ↩ / ⟵ / ↓，需要时改写成文字。
- 虚线箭头两种语义，靠颜色区分：**蓝色虚线 = 库存缓冲联动（非顺序衔接）**；**灰色虚线 = 跨泳道交棒**。
- 箭头标签必须有纸色遮罩（`fill:#fafafa`），遮罩底边离线 6–10px，不得压线、不得压节点。
- 同一节点同一边引出多条线时，挂点间距 ≥12px。

## 8. 图例

- 每张 SVG 底部一条横线图例（分隔线 + 色样 + 文字），覆盖该图用到的全部节点/线条类型，不多不少。
- 主线图例 8 项：流程节点 / 枢纽页 / 入口出口交棒 / 资产分类 / BOM 自动计算 / 决策备注 / 跨泳道交棒虚线 / 📎 弹窗。
- 支线图例 5 项：页面节点 / 枢纽页 / 主线衔接入口 / 流程方向 / ⟷ 双向联动。

## 9. 弹窗与脚本（功能性，保留）

- `SRC_DATA`：每条泳道/财务通道一条，存会议原话+时间戳+拍板记录。新增泳道必须同步补 `SRC_DATA` 条目和 📎 标签。
- `showSrc()` 与 ia-fix 死按钮反馈脚本为原型标准件，勿删勿改接口。

## 10. Mermaid 源数据

- 页尾 `<details>` 默认折叠，仅作信息记录，页面不引入 mermaid.js。
- 结构与主线一致：subgraph 按 B1/L1–L4/T1/T2/F1/F2/S 分区；BOM 自动环节用 `-.->` 虚线；T1 三分支带 `|①②③|` 标签。
- **每次改图必须同步改 Mermaid 源**，两者不允许漂移。

## 11. 修改流程（每次改图必走）

1. **先备份**：复制当前文件到 `_scan_tmpdir/backup-导航图F01-YYYYMMDD/`，带版本说明命名。
2. 施工遵守本文件全部规则。
3. 验证三件事：
   - 浏览器实测文字溢出（`getComputedTextLength` 对照节点框宽，结果必须为 0 处溢出）；
   - 全部 `href` 目标文件存在（grep + 文件检查）；
   - 📎 弹窗开合正常、Mermaid 折叠区开合正常。
4. footer 追加版本记录（`vX.Y（MM-DD 内容）：…`），头部 eyebrow 同步版本号。
5. 若改动涉及规则本身，**同步修订本文档**。
